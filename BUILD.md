# Building Living Cyrodiil

These steps build the same release zip that's uploaded to Nexus Mods (`LivingCyrodiil-<version>-alpha.zip`), on Windows 10 or 11.

## 1. Install the tools

| Tool | Version | Why |
| --- | --- | --- |
| Git | any recent | fetches this repository and the xOBSE source |
| Python | **3.14** (64-bit) | the companion, the `.esp` builder and the packaging script |
| Visual Studio Community | 2019 or newer | builds the 32-bit plugin with the **v142** toolset |

### Python 3.14

Install Python 3.14 from https://www.python.org/downloads/ (or run `py install 3.14` if you already have the Python install manager). Make sure the `py` launcher is installed; the scripts use `py -3.14`.

### Visual Studio

1. Download **Visual Studio Community** (free) from https://visualstudio.microsoft.com/downloads/.
2. In the installer, on the **Workloads** tab, tick **Desktop development with C++**.
3. On the **Individual components** tab, also tick:
   * **MSVC v142 - VS 2019 C++ x64/x86 build tools (Latest)**: xOBSE is built with this toolset.
   * **C++ ATL for v142 build tools (x86 & x64)**: xOBSE's headers need it. Pick the entry that mentions v142 or 14.29, not "C++ ATL for latest build tools".
   * A **Windows 10 SDK** or **Windows 11 SDK** (usually ticked already).
   * **MSVC v143 or newer, x64/x86 build tools** (ticked with the workload). The release packaging copies the Visual C++ runtime DLLs from this toolset's `VC\Redist` folder.
4. Click **Install** and restart if asked.

## 2. Get the source

```
git clone --recurse-submodules https://github.com/MVXK21/Living-Cyrodiil.git
cd Living-Cyrodiil
```

If you cloned without `--recurse-submodules`, run `git submodule update --init`. The xOBSE source goes in `external\xOBSE`, pinned to release 22.13.

## 3. Build the plugin and the .esp

From the repository folder:

```
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

This compiles `plugin\LivingCyrodiil.sln` (Release, Win32) with MSBuild and writes `LivingCyrodiil.esp` with `tools\build_esp.py`. The `.esp` is generated by a script, never edited by hand. The result goes in `build\package\`:

```
build\package\LivingCyrodiil.esp
build\package\OBSE\Plugins\LivingCyrodiil.dll
build\package\OBSE\Plugins\LivingCyrodiil.ini
```

If a Visual Studio component is missing, the script names it.

## 4. Set up the companion's Python environment

```
powershell -ExecutionPolicy Bypass -File companion\setup.ps1
```

This creates `companion\.venv` with Python 3.14 and installs the libraries in `companion\requirements.txt` from PyPI: openai, numpy, sounddevice, faster-whisper, useful-moonshine-onnx, pocket-tts (which pulls in PyTorch, CPU build) and pytest.

Optional: run the tests. They're offline and need no API key.

```
companion\.venv\Scripts\python.exe -m pytest companion\tests
```

## 5. Package the release zip

```
companion\.venv\Scripts\python.exe tools\make_release.py
```

This takes a few minutes and writes `build\release\LivingCyrodiil-<version>-alpha.zip`. It contains:

* the files from `build\package\`;
* `LCCompanion\`: the companion's code (`companion\living_cyrodiil`), its data (`companion\data`), and `LCCompanion\python\`, a bundled copy of Python 3.14 made of:
  * the base Python install the venv was created from (minus tests, IDLE and tkinter);
  * the venv's `site-packages` (minus pip and build-only files such as headers);
  * the Visual C++ runtime DLLs from Visual Studio's redistributable folder, placed next to `python.exe` because PyTorch, CTranslate2 and ONNX Runtime need them;
* `PASTE YOUR API KEY HERE.txt`, `Collect logs.bat` (zips the mod's logs onto the desktop for bug reports), the README and COPYRIGHT.md.

The script stops if an API key, a personal settings file, logs, memory or downloaded models would end up in the zip.

## About the files in the release

* **`LivingCyrodiil.dll`** is built from `plugin\src`. At game load, it starts `LCCompanion\python\python.exe` hidden, with no console window (`plugin\src\companion_launch.cpp`). It uses a Windows job object so the companion closes when the game does, and it doesn't start a second copy if one is already running. It can be turned off with `AutoStart=0` under `[Companion]` in `LivingCyrodiil.ini`.
* **`python.exe`, `pythonw.exe`, `python3.dll`, `python314.dll` and everything in `LCCompanion\python\`** are unmodified files from the official Python 3.14 install and the PyPI packages listed above.
* **`msvcp140*.dll`, `vcruntime140*.dll`, `concrt140.dll`** are Microsoft's redistributable Visual C++ runtime, which Microsoft allows apps to ship beside their own files.
* Nothing is downloaded or run at install time. At first launch, the companion downloads its speech-to-text and voice models from Hugging Face into `Documents\My Games\Oblivion\LivingCyrodiil\models`.

## Running from source (for development)

Install `build\package\` as a mod, set `AutoStart=0` in `LivingCyrodiil.ini`, and run the companion from its venv:

```
powershell -ExecutionPolicy Bypass -File companion\companion.ps1
```

See `companion\README.md` for its settings and test tools.
